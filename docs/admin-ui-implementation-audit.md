# 管理 UI 実装監査

監査日: 2026-08-28

`admin-ui-design.md` の受け入れ基準を、API 管理画面、Collector 管理画面、公開 API、ReadModel、永続化処理と照合した結果を記録する。

## バックエンドの対応状況

| 要件 | 状況 | 補足 |
|---|---|---|
| ジョブ検索・詳細 API | 対応済み | `/api/collection/tasks` と `/{jobId}` |
| `jobId` ベースの再投入 | 対応済み | `/api/collection/tasks/{jobId}/requeue` |
| 楽観的同時実行制御 | 対応済み | `ExpectedUpdatedAt` が不一致なら 409。Store も `Conflict` を返す |
| 再投入前の確認 | 対応済み | ジョブ詳細で二段階操作 |
| 再投入監査履歴 | 未実装 | 操作者、理由、旧状態、新状態、時刻を保持するテーブルが必要 |
| 親子ジョブ関係 | 未実装 | DTO と永続化モデルに親 JobId がない |
| 人馬の共通参加履歴 DTO | 未実装 | 現在は Horse / Jockey 別 DTO。画面がレース API を追加取得して補完している |
| 調教師の参加履歴 API | 未実装 | 調教師詳細の関係表示を阻害している |
| Owner API / 永続化 | 未実装 | 現在は `OwnerName` snapshot のみ |
| レース関連ジョブ API | 未実装 | API 管理画面と Collector 管理画面の横断導線がない |
| UI エラーの型付き応答 | 一部対応 | 更新系は検証エラーを扱うが、参照系の通信エラー状態が不足 |

## 次の実装順序

1. 再投入監査履歴と親子ジョブ参照を追加し、旧形式の再投入 API を段階的に廃止する。
2. 共通 `ParticipationHistory` DTO と調教師履歴 API を追加し、馬・騎手画面の N+1 取得を解消する。
3. レース詳細の出走・結果を参加オブジェクトへ統合し、関連する人馬と予想票を接続する。
4. Owner Aggregate / ReadModel / API / 画面と、既存 `OwnerName` の名寄せ候補を追加する。
5. 残る一覧をモバイル用オブジェクト一覧へ置換し、320 / 360 / 736 / 1024 px と 200% 拡大で全ルートを検証する。

この文書で「未対応」とした項目は、デザイン完了ではなく実装バックログとして扱う。
