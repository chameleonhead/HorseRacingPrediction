# 開催日単位でJRAレースデータを再取得する

- Status: Proposed
- Owner: HorseRacingPrediction team
- Created: 2026-09-09
- Updated: 2026-09-09

## Context

過去に取得した出馬表には、抽出ロジック改善前のデータなど、馬主が欠落している出走情報がある。現在はレース詳細から1レースずつ `RaceReacquisition` を依頼できるが、開催日内の全レースを補完するには個別操作を繰り返す必要がある。

通常の `RaceCardCollection` は発走後の自動再訪を止めるため、終了済み開催日を再登録しても出馬表詳細を取得しない。今回の操作は管理者が明示する修復であり、この自動停止条件とは分離する必要がある。

実装後の確認で、日付親ジョブの対象列挙がAPI登録済みレースに限定され、公式サイトには存在するがDBに未登録のレースを再構築できないことが判明した。また、レース単位の再取得が対象日にかかわらず出馬表を試すため、公式掲載期間外への不要なアクセスと、結果だけ取得できた場合の完了意味が曖昧になっている。

## Goals

- JSTの日付を1日指定し、その日にJRAで開催された全競馬場・全レースを再取得できる。
- 出馬表に掲載される馬主を含め、レース基本情報、出走情報、公開済み結果・払戻をJRA公式情報で更新する。
- 1回の長い処理にせず、日付親ジョブからレース単位の既存再取得ジョブへ分割し、進捗と部分失敗を追跡できる。
- 通常の自動取得停止状態や過去の成功履歴を壊さず、管理者の明示操作だけで再取得する。
- DB登録状況に依存せず、JRA公式の開催日程とレース一覧から指定日の全対象レースを再発見する。
- 出馬表を取得するかは対象日と公式出馬表の探索期間から自動判断し、結果・払戻とは独立して扱う。

## Non-goals

- 指定期間や全期間を一度に再取得する操作は含めない。実行単位は1日とする。
- NAR・海外競馬は対象外とする。
- 馬、馬主、騎手、調教師のプロフィールや馬の全出走履歴を連鎖的に再取得しない。
- JRAで取得できない値を推測しない。取得不能値で既存値を消さない。
- 通常の自動収集を再開したり、出馬表取得終了マーカーを解除したりしない。

## Experience and interaction design

API管理画面の収集ジョブ一覧 `/jobs` に補助操作「開催日を再取得」を置く。日付を必須入力し、確認ダイアログで次を表示する。

- 対象日とProvider（JRA固定）
- 全競馬場・全レースの基本情報、出馬表、出走馬・馬主、公開済み結果・払戻を更新すること
- 取得できなかった項目では既存値を消さないこと
- レース数に応じて複数ジョブへ分割され、完了まで時間がかかること

送信成功後は親ジョブ詳細へ遷移し、発見レース数、成功数、実行中数、失敗数を確認できる。同じ日付の再取得が有効状態なら二重依頼を受け付けず、既存親ジョブへのリンクを返す。

## Navigation and relationships

`/jobs` → 「開催日を再取得」→ 確認 → 日付親ジョブ `/jobs/{jobId}` → 集約対象の各 `RaceReacquisition` → 対象レース詳細。

## Technical impact

- 日付親ジョブ `RaceDayReacquisition` と、JRA・対象日・依頼者・理由を持つペイロードを追加する。
- 管理APIに日付再取得のPOSTと、同日付の最新依頼を確認するGETを追加する。既存の管理認証・書き込み権限を適用する。
- 親ジョブはAPIの登録済みレース検索を対象列挙に使わず、JRA公式の開催日程と対象日に適したレース一覧導線から全競馬場・全レースを発見する。未登録レースも公式識別子、開催場、レース番号から子ジョブ化できるようにする。
- 出馬表の対象日は既存の `RaceCardLookupPeriod`（JST基準、既定は当日から過去5日以内、および将来日）で判定する。対象内なら出馬表を取得し、対象外なら出馬表ページへアクセスしない。
- 当日以前は結果・天候・馬場・払戻を取得する。将来日は結果ページへアクセスしない。したがって、同じ子ジョブでも対象日により「出馬表のみ」「出馬表と公開済み結果」「結果のみ」を自動選択する。
- 未登録レースは、最初に取得できた出馬表または結果の基本情報で新規登録してから、同じレースの残りの公開情報を更新する。既存レースは同一性を検証して更新する。
- 子ジョブの冪等キーは親ジョブIDとJRAレースIDを含める。同一親内では重複せず、後日の新しい明示依頼では再取得できる。
- 親の集約は既存の成功・失敗・保留・再実行規則を使用する。親のリランでは成功済み子を維持し、失敗または未作成の子だけを再開する。
- 日付再取得は利用者起点の高優先度とし、自律バックフィルより先に配送する。ただしRunningジョブを中断しない。

## Decisions

### 採用: 日付親ジョブから既存レース再取得へ分割する

最大3場・36レース程度を1つのLambda実行で直列取得すると14分期限を超える可能性がある。日付ジョブは発見と分割だけを行い、保存ロジックは検証済みのレース単位再取得を再利用する。

### 採用: 「全データ」はレース単位の公式公開データとする

対象はレース基本情報、出馬表、出走情報（馬主を含む）、公開済み結果、天候・馬場、払戻である。馬プロフィール・全履歴まで連鎖させると1日の操作から無制限に範囲が広がるため含めない。

### 採用: 自動取得終了状態は変更しない

今回の修復は一度だけの明示操作であり、日付マーカーを解除すると以後の15分・定期計画で不要アクセスが再開するため、既存状態から独立した親子ジョブにする。

### 採用: 公式一覧から再発見し、対象日で取得経路を選ぶ

完全再取得の対象集合はDBではなくJRA公式情報から決める。出馬表は掲載期間が短いため、`RaceCardLookupPeriod` 外では存在確認を繰り返さず、過去日用の結果一覧からレースを列挙する。期間内は出馬表一覧、当日以前は結果一覧も参照し、片方だけに現れるレースを落とさないよう公式識別子で和集合・重複排除する。

## Acceptance criteria

- 管理者がJSTの日付を1つ指定してJRA開催日再取得を依頼できる。
- 開催日なら全開催競馬場・全レースが発見され、レースごとに有効な再取得子ジョブが1件登録される。
- APIに一件も登録されていない開催日でも、JRA公式一覧に存在する全レースが発見・新規登録される。
- `RaceCardLookupPeriod` 内の日は出馬表を取得対象とし、期間外の日は出馬表一覧・詳細へアクセスせず結果一覧から対象を発見する。境界日はJSTで判定する。
- 将来日は結果を取得せず、当日以前は公開済みの結果・天候・馬場・払戻を取得する。
- 各レースで基本情報、出馬表、全出走情報と馬主、公開済み結果・天候・馬場・払戻が再取得対象になる。
- JRAから取得できた値は既存値を更新し、取得できない任意項目で既存値を消さない。
- 終了済み開催日と日次結果 `Complete` の日でも明示再取得を実行できるが、自動取得終了マーカーを解除しない。
- 開催なしの日は子ジョブ0件で正常完了し、「JRA開催なし」と確認できる。
- 同じ日付の親が Ready / Running / WaitingDependency / Held の間は重複作成せず、既存ジョブを返す。成功・失敗の終端後は新しい依頼を作成できる。
- 親詳細で対象数、成功、実行中、失敗を確認でき、各子からレース詳細へ遷移できる。
- 一部レースが失敗した場合、親は失敗対象を示し、リラン時に成功済み子を再取得しない。
- 全体停止中は依頼を永続化しても配送・新規リースを開始せず、再開後に処理する。
- 常駐Collectorと `--once` / Lambdaで同じ分割・更新・集約結果になる。
- 既存のレース単位再取得、通常収集、発走後自動停止、予想データ、手動訂正監査に回帰がない。

## Delivery plan

1. 日付親ジョブ、ペイロード、原子的な重複抑止、監査・outbox登録を状態ストアへ追加してテストする。
2. 管理API・ApiClientと `/jobs` の日付入力・確認・親詳細導線を実装し、権限、入力エラー、重複をテストする。
3. CollectorでJRA開催・レース発見と既存 `RaceReacquisition` 子への分割、空日、部分失敗、親集約・リランを実装してテストする。
4. 馬主を含む既存値更新と欠損時保持を、保存APIおよびワークフローの統合テストで検証する。
5. 常駐・`--once` の回帰、全体ビルド、ドキュメント同期を行う。
6. DB未登録の開催日、出馬表探索期間の内側・境界・外側、将来日、開催なし日を自動テストし、可能な範囲でJRA実サイトの小規模な日付を使った動作確認を行う。実サイト検証では対象数、作成数、出馬表アクセス有無、結果・払戻、馬主保存、重複排除を記録する。

## Deviations and follow-up

- 対象レースの列挙はJRAサイトを親ジョブで再探索せず、APIに登録済みの同日レースを正本として行う。今回の目的が「保存済みデータの馬主欠落補完」であり、未登録レースには更新対象が存在しないためである。個々の子ジョブはJRA公式ページを再取得する。未登録レースの発見・新規作成は自律バックフィルの責務として分離する。
- JRA側で過去の出馬表が公開範囲外の場合は結果だけが更新され、馬主は補完できない。対象レースの子ジョブ状態から公開範囲外を確認できる。
- 複数日・期間指定、馬主欠落レースだけを自動抽出する最適化、日付再取得の一括キャンセルは別変更とする。
