# 収集ジョブ一覧・詳細ワイヤーフレーム

既存の [オブジェクトナビゲーション変更におけるジョブ画面モック](../../20260829_seamless-admin-object-navigation/mocks/jobs.md) を引き継ぎ、Fluent UI、canonical route、状態別 view、technical disclosure を追加定義する。

## 一覧 / desktop / 1280 CSS px / 要対応・loaded

```text
┌──────────────────┬──────────────────────────────────────────────────────────────┐
│ RaceOps          │ 収集ジョブ                                                       │
│                  │ 収集処理の進行状況を確認し、失敗から復旧します              │
│ レース・予想     │                                                              │
│   レース         │ [要対応 3] [処理中 2] [待機中 14] [最近完了] [すべて]       │
│   予想票         │ [対象を検索………………] [処理種別 ▾] [対象日 ▾] [filter]       │
│                  │                                                              │
│ データ           │ 要対応                                               3件     │
│   馬             │ ┌──────────────────────────────────────────────────────────┐ │
│   騎手           │ │ レース結果の収集                  デッドレター 10:36  › │ │
│   調教師         │ │ JRA・2026年8月28日・札幌 9R                           │ │
│   馬主           │ │ 3回失敗・結果と払戻が未更新                           │ │
│                  │ ├──────────────────────────────────────────────────────────┤ │
│ 運用             │ │ 日次収集                            依存待ち 10:32  › │ │
│ ジョブ           │ │ JRA・2026年8月28日                                    │ │
│                  │ │ 親ジョブの完了待ち・19 / 24レース完了                  │ │
│                  │ └──────────────────────────────────────────────────────────┘ │
└──────────────────┴──────────────────────────────────────────────────────────────┘
```

- collection header に件数、view、filter をまとめる。初期化や再投入のような object-scoped でない危険操作は置かない。
- `JobType` ではなく人が読める処理名、`DeduplicationKey` ではなく対象日・開催・レースを主にする。
- state は和文ラベルと色を基本とし、必要な場合だけ Fluent システムアイコンを補助的に使う。絵文字は使わない。
- row は job object の縮約表現であり、詳細への移動だけを primary interaction とする。

## 詳細 / desktop / 1280 CSS px / dead letter

```text
← 収集ジョブ / 要対応

レース結果の収集                         [デッドレター]         [再投入する]
JRA・2026年8月28日・札幌 9R              10:36 更新

┌─ 要確認 ────────────────────────────────────────────────────────────────┐
│ 3回連続で取得に失敗し、結果と払戻が未更新です。                         │
│ JRAページの応答が30秒以内に返りませんでした。                           │
└────────────────────────────────────────────────────────────────────────┘

主要な情報
試行回数  3回       初回投入 09:58       最終試行 10:36

ジョブ階層
親ジョブ     [日次収集 ›]                JRA・8月28日 / 19 of 24完了 / 10:32更新
  └ 現在     [レース結果の収集]            札幌9R / デッドレター / 3回失敗 / 10:36更新
      ├ 子   [出馬表の収集 ›]              札幌9R / 完了 / 09:48更新
      └ 子   [払戻の収集 ›]                札幌9R / 待機中 / 10:36更新

関連するオブジェクト
対象日       [2026年8月28日の収集ジョブ ›]
対象レース   [札幌 9R ›]

履歴
10:36  失敗         Timeout / 3回目
10:31  実行開始     Collector Lambda
10:26  再投入       admin / 理由: JRA復旧を確認
09:58  初回投入

[› 技術情報]
```

- object header は識別、状態、更新時刻、状態依存 CTA を一体として扱う。
- error は payload や stack trace より前に、人が読める影響と次の行動を示す。
- 関係はラベル付き `RaceOpsEntityLink` とし、job 詳細を行き止まりにしない。
- 操作履歴と実行状態履歴は一つの timeline に統合する。
- payload、lease、Job ID は primary action / content ではないため disclosure へ置く。

```text
│ レース結果の収集               │
│ JRA・8月28日・札幌 9R          │

│                                │

│                                │
│ 要確認                         │
│ 3回連続で取得に失敗            │
│ 結果と払戻が未更新です         │
│                                │

再投入 dialog / bottom sheet
┌────────────────────────────────┐
│ この収集ジョブを再投入しますか？   │
│ レース結果の収集               │
│ JRA・8月28日・札幌 9R          │
│                                │

│                                │
│ [キャンセル] [再投入する]      │

```

- 320 CSS px では横長 table や tab row を使わず、object の読み順を縦に保つ。
- bottom sheet を使う場合も dialog semantics、initial focus、Escape、focus return、busy state を満たす。
- 成功後は詳細へ戻り、状態と timeline が更新されたことを画面本文で確認できる。

## Edge states

- **Loading**: object header の skeleton / progress と「収集ジョブを読み込み中」を示す。
- **Not found**: 指定 Job ID、一覧へ戻る、URL再確認を示し、空の詳細 card は表示しない。
- **Permission denied**: 閲覧不可と操作不可を区別する。権限のない CTA を一瞬表示しない。
- **Conflict**: 「更新されていたため実行しなかった」と明記し、最新 object を再表示する。
- **Relationship unavailable**: ID が取得できない関係は未実装リンクにせず、関係ラベル付きテキストとする。
