# レース詳細からの再取得依頼

- Status: Approved
- Created: 2026-09-08
- Updated: 2026-09-08

## Context

レース名の抽出不具合を修正した後、利用者がレース画面から対象データを再取得できるようにする。
[レース名抽出修正](../20260908_jra-race-name-course-text/README.md)と合わせて承認・実装する。

現状、`RaceDetail.razor` の先頭操作は編集のみ。取得状況画面の再取得は成功済み元ジョブを複製するため、開催日全体の収集が再実行され得る。過去レース個別収集の旧インターフェースは残っているが、Collectorの実装登録は無効化されている。稼働中の `CollectionExecutionService` に対象レース専用の実行経路が必要。

## Goals

- レース詳細から、その1レースだけをJRAから再取得する依頼を送る。
- 元ジョブの有無や成功履歴に依存せず依頼できる。
- 受付と取得完了を区別し、状態と結果をレース画面で確認できる。

## Scope proposal

確定範囲は、レース名・条件・公開されている出走情報・結果・払戻の全項目。再取得で判明した変更はすべて更新する。

取得した項目はJRAの値で更新する。未公開・取得不能の項目で既存値を消さない。予想、購入情報、利用者メモは対象外。馬・騎手等のプロフィールや過去成績を連鎖的に全件再取得する操作にはしない。

## Experience and interaction design

- `/races/{RaceId}` のヘッダーに「JRAから再取得」を追加する。既存の編集を併置する。
- 確認ダイアログで日付・競馬場・R・レース名、再取得範囲と「取得した項目はJRAの情報で更新します」を表示。「キャンセル」「再取得を依頼」を提供する。
- 受付後は詳細画面に留まり、取得状況に「受付済み」「取得中」「完了」「失敗」を文字で表示する。ジョブ詳細へのリンクを付ける。
- 表示中は状態を定期照会し、成功時にレース情報を再読込する。失敗時は既存情報と分かりやすい理由を表示し、再依頼を可能にする。部分失敗を全体成功と表示しない。
- 依頼送信中および同レースの依頼が待機・実行中の間は重複操作を抑止する。画面再訪時も最新依頼を確認する。
- レース未検出、JRA対象外、識別情報不足では依頼不可の理由を表示する。結果未公開だけで取得済みの出馬表を失敗扱いにしない。全対象が未公開の場合は「公開待ち」を明示し、既存ジョブ方針に沿って再試行する。
- 狭い画面では操作を折り返す。Fluentコンポーネントを使用し、キーボード操作、ダイアログのフォーカス移動・復帰、状態通知を検証する。

## Navigation and relationships

レース一覧 → レース詳細 → 再取得依頼。レース詳細の取得状況 → ジョブ詳細。ジョブ詳細から対象レースへ戻れるようにする。一覧の各行には操作を増やさない。

## Technical impact

- 管理APIにレースIDを指定した再取得依頼POSTと最新依頼のGETを追加する。既存の認証・書き込み権限を適用する。日付・競馬場・Rはサーバー上のレース情報から解決する。
- POSTはジョブIDと照会先を返す。サーバー側で同レースの有効な依頼を原子的に重複抑止し、二重クリック・別タブ・同時リクエストでも1件だけ投入する。完了・失敗後の明示的な再依頼は新しい履歴として残す。
- 専用ジョブ種別・ペイロードを既存の永続ストア、キュー配送、稼働中Collectorの常駐・`--once` 両経路へ統合する。日別収集済みマーカーによるスキップを適用しない。依頼者・対象・時刻を監査記録に残す。
- JRAナビゲーションと結果パーサー・保存経路を再利用する。出馬表ワークフローには対象レース指定の経路を追加し、同日他レースを保存しない。URLは推測生成せず、既存のナビゲーションから解決する。
- 指定レースと取得ページの同一性を検証し、別レースを更新しない。現在の決定的IDによる保存経路も確認し、画面で指定したレースが更新されることを保証する。
- 保存済み結果・払戻について、再宣言のスキップだけで変更が失われないよう既存の訂正契約を確認する。承認された範囲内で取得した変更が反映され、ライフサイクルや関連データの整合性を保つ。
- 既存データの削除や一括再収集は行わない。元の `PlaywrightWebBrowser.cs` 未コミット変更を混在させない。

## Acceptance criteria

1. レース詳細から1件の再取得依頼を送り、受付とジョブリンクを確認できる。
2. 元ジョブなし・日別取得済みでも指定レースだけを実際に再取得する。
3. 2026年9月6日中山6Rの誤ったレース名が「メイクデビュー中山」に訂正され、完了後の詳細に表示される。
4. 確定した範囲の公開済み情報を更新し、未取得値で既存情報を消さない。確定済みレースでも再取得できる。
5. 同時依頼、別タブ、画面再訪で重複ジョブを作らない。完了・失敗後は再依頼できる。
6. 未認証、対象外、レース未検出、送信失敗、収集失敗、部分失敗、公開待ちの表示とAPI応答が正しい。
7. 常駐Workerと`--once`の双方がジョブを実行できる。
8. 360pxで横溢れせず、キーボードから依頼・キャンセル・状態確認ができる。
