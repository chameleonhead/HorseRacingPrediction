## Frozen scope and decisions

- 指定した一つのHorseIdに対する同期・読み取り専用診断。domain/collectionデータ、schema、queue、job状態を変更しない。診断にschema migrationやSaveChangesを伴わせない。
- 現在の馬情報、sequence 1登録時のRegisteredName/NormalizedName、JRA profileのsource、該当するJRA Horse resourceのsourceIdentity/sourceUrlを別々の根拠として返す。同名だから同じ馬という判定はしない。現在のresolverを変更しない。
- 旧ルール/現行ルールで算出したIDは比較材料であり、実体同一性や移行適格性の証明ではない。欠落・不正・未知の形状・複数の矛盾を明示し、安全な移行候補へ読み替えない。
- 読取時刻と対象、確認範囲を表示する。DB間の読取は共通transactionではなく、全データの同時点snapshotや実行可能な移行計画ではない。結果の永続journalや新しい常駐loopは追加しない。再起動後は再取得する。
- GETの入力はHorseIdだけ。SQL、shell、パス、接続文字列、APIキー、移行先IDを受け取らない。生イベントJSON、全DBdump、内部例外、秘密情報を返さない。
- 設定画面から専用の診断Pageへ遷移。HorseId入力と「診断」、結果の「再取得」のみ。移行実行・再開・リセットのボタンは設置しない。
- 認証済みUI→server-side AdminApiClient→APIキー保護APIを維持。権限モデルを推測で増やさず、APIキーをbrowserへ渡さない。
- 入力はcanonical `horse-` + GUID D形式だけ、ordinalで照会する。不正形式は400で、名前検索・case-fold・代替ID採用をしない。非canonicalな過去IDの全件調査は親recordに残す。
- event Data/Metadata、resource AttributesJsonは各64KiB以内でSQL側のlength guardを通過したものだけ取得し、JSON depthは16。sourceはoriginごと16+1件で超過を検出、16件まで表示しtruncatedを明示。sequence 1は最大2件で重複検出。同期診断は全体30秒、同時実行1件・待ち行列なし（429）、cancelを伝播。businessの書込gateを占有せず、新loopなし。
- sourceIdentityは正規化したJRA識別子だけをwireへ返す。sourceUrlはraw値を返さず、別の検証状態と抽出したJRA識別子を返す。不正な任意文字列はstatusのみとし、URL内認証情報や秘密queryの流出を防ぐ。
- 専用connectionをserver設定/既存DbContext optionsから導出しReadOnly/query_onlyで読取。新規ファイル作成・migrator起動・SaveChanges不可。各store内だけread transaction、別々の観測時刻。identifying metadata/type/field shapeが登録済みHorseRegisteredと一致すると確認できないイベントはUnsupportedで、登録の証明に用いない。assembly versionをpayload schema versionに読み替えない。exact library APIの選択はこの意味を守る内部実装判断。
