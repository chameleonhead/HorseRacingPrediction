# 設定画面: 主体IDマイグレーション（テキストワイヤーフレーム）

対象: `/settings`、desktopとnarrow viewport。既存の低頻度管理操作の中に独立sectionとして追加し、通常の設定項目と混在させない。

```text
その他設定
通常の編集や収集管理とは別の、低頻度の管理操作です。

主体IDマイグレーション
保存主体と収集ジョブのID不一致を検出し、安全な対象だけを復旧します。

[候補を確認]

最終確認: 2026/09/18 10:30   Manifest: ...   [再確認]
┌────────┬────┬────┬────┬────┬────┬────┐
│修復可能 12 │再利用 3 │対象外 2 │曖昧 1 │証拠不足 4│実行中 1│衝突 0│
└────────┴────┴────┴────┴────┴────┴────┘

絞り込み: [主体種別] [判定] [検索]

☐ 状態       主体       現在ID → canonical ID       根拠          予定操作
☑ 修復可能   競走馬     horse-... → horse-...       JRA識別子、RaceEntry
☐ 要確認     調教師     trainer-...                 同名候補2件    自動処理しない
☐ 対象外     馬主       owner-...                   alias不明      要対応を維持

安全に実行できる 12件中 3件を選択
                                      [選択した対象を移行]
```

実行前確認Dialog:

```text
主体IDマイグレーションを実行しますか？

3件の参照をcanonical IDへ収束し、必要なRecoveryジョブを作成します。
元のジョブ・試行・通知履歴は削除しません。
preview後に状態が変わった対象は実行せず、結果に理由を表示します。

[キャンセル] [3件を移行]
```

## Interaction contract

- 初回表示では変更を行わず、説明と`候補を確認`だけをPrimary Actionとして表示する。
- preview後は分類件数を先に、その後に対象、根拠、予定操作を表示する。内部IDは調査情報として主体名の下に置く。
- `SafeToExecute`相当の対象だけ選択可能にし、曖昧、証拠不足、Running、衝突は無効表示と理由を示す。
- applyにはpreviewのmanifest tokenと選択Candidate IDを渡す。previewが古い、候補が変化した、または実行中になった場合は適用せず再previewを促す。
- 実行中はPrimary Actionを無効化し進行状態を表示する。二重送信しない。
- 完了後は適用、既存Task再利用、skip、失敗を件数と対象別理由で表示し、自動的に再previewする。
- API失敗時も選択とpreview結果を保持し、再試行または再previewのどちらが必要か示す。
- narrow viewportでは分類を縦に折り返し、表は対象単位のcardへ切り替える。状態、主体、根拠、予定操作、選択、Primary Actionを省略しない。
- keyboardだけでpreview、絞り込み、選択、確認、キャンセル、applyができ、状態を色だけで区別しない。

## Page/dialog decision

候補調査と既存の補正操作がすでに`/settings`に集約されているため、入口とpreview結果は同ページの独立sectionに置く。実行確認だけは短時間で完了し、previewのcontextを維持するためDialogを使う。大量候補の詳細調査が必要な場合は既存ジョブ詳細へのリンクを使い、Dialogへ履歴を詰め込まない。
