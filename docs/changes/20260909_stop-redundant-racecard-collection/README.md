# 発走時刻到達後の出馬表自動取得を停止する

- Status: Approved
- Owner: HorseRacingPrediction team
- Created: 2026-09-09
- Updated: 2026-09-09

## Context

`ScrapingRegistrationService` は、JST の当日から `ScheduleLookaheadDays` 先までの開催日について、同じ日付キーの `RaceCardCollection` を定期的に登録する。`ProcessingStateStore.ScheduleJobAsync` は親を持たない成功済みジョブを再登録すると `Succeeded` から `Ready` に戻す。この組み合わせにより、出馬表取得が成功した開催日も定期サイクルごとに再実行され、当日の全レース終了後も同じ出馬表を探しに行く。

出馬表には、初回公開後も出走取消、騎手変更、馬体重など発走前に変わり得る情報があるため、最初の成功だけで以後の自動更新をすべて止めることにも不利益がある。一方、発走時刻到達後は出馬表の役割が終わり、以後は結果収集が担当するため、出馬表を再訪する必要はない。

この変更では、取得の必要性をレース単位で判定し、発走前の鮮度維持と終了後の不要アクセス削減を両立する。

## Goals

- 公式発走時刻に到達した、または公式結果確認済みのレースについて、出馬表詳細を自動で再取得しない。
- 未公開の出馬表は公開見込み時刻まで待ち、公開後も発走前に限って必要な更新を取得する。
- 同じ開催日の一部レースが終了していても、未発走レースだけを更新対象にできるようにする。
- 開催日の全レースが出馬表取得終了状態になった後は、日付単位の出馬表ジョブを定期計画から再登録しない。
- 管理者が明示するレース再取得は、自動停止条件にかかわらず従来どおり利用できる。

## Non-goals

- JRA の公開時刻を外部カレンダーから予測する新サービスは追加しない。
- 発走後の訂正検知を出馬表から行わない。訂正は結果収集または手動再取得で扱う。
- 出馬表取得ジョブを日付単位から完全なレース単位へ作り替えない。
- 出馬表の項目・Parser・ドメインモデル自体は変更しない。
- 専用の管理画面は追加しない。

## Experience and interaction design

自動運用では、管理者が停止操作を行わなくても、対象レースの発走時刻を過ぎると出馬表更新対象から外れる。開催日の全レースが対象外になれば、その日付のジョブは成功した出馬表取得終了状態を維持する。この状態はレース結果の公式確定を意味しない。

既存のジョブ詳細とレース別取得状況には、処理件数に加えて次の区別を表示できる状態を返す。

- 更新したレース
- 公式発走時刻に到達した、または公式結果確認済みのためスキップしたレース
- 未公開のため再試行するレース
- 解析・通信エラーで再試行するレース

出馬表取得終了後でも、レース詳細の「JRAから再取得」は使用できる。これは訂正対応の明示操作であり、自動ジョブを再び周期実行に戻さない。

## Navigation and relationships

```text
定期 CollectionPlanning
  └─ 開催日ごとの必要性を確認
       ├─ 更新対象レースあり ──> RaceCardCollection を登録
       └─ 全レースが出馬表取得終了 ─> 成功状態を維持して登録しない

RaceCardCollection（日付単位）
  ├─ 未発走・結果未取得 ─────> 出馬表詳細を取得
  ├─ 発走済み ─────────────> 詳細取得をスキップ
  └─ 公式結果確認済み ───────> 詳細取得をスキップ
```

開催選択・レース一覧までの最小限の確認は、同日の未発走レースを発見するために許容する。各レースの出馬表詳細ページへの遷移を停止対象とする。

## Technical impact

### 公式上の確定とシステム上の取得終了

JRA は、レース終了後に到達順位を表示し、その後「確定ランプ」が点灯した時点をレースの確定としている。確定後に払戻金が発表される（[JRA「レースの確定」](https://www.jra.go.jp/keiba/rules/kakutei.html)）。

JRA 公開ページに機械判定専用の安定した確定フラグがあることは確認できていないため、本システムでは次の状態を混同しない。

| 状態 | 判定 | 用途 |
|---|---|---|
| 出馬表取得対象 | 公式発走時刻より前 | 出馬表の初回取得・発走前更新を許可する |
| 出馬表取得終了 | 公式発走時刻に到達、または公式結果確認済み | 出馬表詳細の自動取得を止める。レース確定を意味しない |
| 公式結果確認済み | JRA結果ページから確定着順と払戻を正常に取得 | 結果取り込みと日別完了判定に使う |

発走時刻は JRA が公開する公式情報を使用するが、その時刻への到達は「発走予定時刻に達した」という取得制御上の判定であり、実際の発走、競走終了、着順確定を証明するものではない。発走時刻変更を取得できた場合は最新値を使う。

現在の `RaceResultStatus=Succeeded` は出走馬結果を1件以上保存できたことを表すため、それだけを公式確定の一般的な定義にはしない。実装では、確定着順と払戻の抽出成功を公式結果確認済みの条件として明示し、出馬表停止とは別に扱う。

### 必要性判定

自動出馬表取得の対象は、次の順で判定する。

1. 公式結果確認済みなら出馬表取得終了とし、出馬表詳細を取得しない。
2. JRA 公開の発走時刻が判明し、現在時刻（JST）が発走時刻以上なら出馬表取得終了とし、出馬表詳細を取得しない。
3. 発走時刻が不明でもレース日が JST の過去日なら出馬表取得終了とする。
4. 上記以外は発走前の更新対象とする。

発走時刻ちょうどから出馬表ではなく結果収集を待つ。レース終了時刻を推定する猶予は設けない。出馬表の役割は発走前情報の供給であり、発走後に内容を更新する必要がないためである。

日付単位では、対象日の全レースが出馬表取得終了、または日別結果状態が `Complete` なら `RaceCardCollection` を再登録しない。一部だけが未発走の場合は日付ジョブを実行するが、レース一覧から出馬表取得終了レースを除外し、未発走レースの出馬表詳細だけを取得する。

発走時刻を取得状態側で参照できない現状を解消するため、Api のレース照会契約からレース ID・日付・競馬場・番号・発走時刻・結果有無を日付単位で取得できるようにする。出馬表収集で取得した発走時刻を正本とし、取得できない場合だけ上記3の安全なフォールバックを使う。

### 再試行と更新間隔

- 未公開でレースが未来の場合は、既存の出馬表発表予定日まで待つ。
- 発表予定日以後に未公開なら、発走前に限って既存の再試行間隔で再試行する。
- 一度成功しても発走前は変更追随の価値があるため、`ScrapingIntervalMinutes` より短い周期では再取得しない形で限定的な更新を許容する。
- 発走時刻到達後は、未公開・失敗状態であっても自動再試行を終了する。失敗理由と最終試行は保持する。
- 一時的な通信・解析失敗は発走前だけ再試行する。成功済みデータを失敗で消さない。
- 全レースの出馬表取得終了後に `ScheduleJobAsync` が成功済み日付ジョブを `Ready` に戻さないよう、登録側で必要性を判定する。汎用 `ScheduleJobAsync` の「明示的な再投入」挙動は他ジョブとの互換のため変更しない。

### 結果収集との境界

発走時刻到達後は `RaceResultCollection` がレース基本情報、出走情報、確定着順・払戻の取得を担当する。結果がまだ公開されていないことを理由に出馬表取得へ戻らない。結果収集が一時失敗しても、出馬表の自動再取得を再開しない。公式結果確認済みになるまでは、レース結果側を未完了として再試行する。

## Decisions

### 採用: 発走時刻到達または公式結果確認を出馬表取得終了条件にする

同一開催日の後半レースだけを更新でき、発走時刻に達したレースの詳細ページへ繰り返しアクセスしない。日付が変わるまで待つ方式より不要アクセスを早く止められる。この判定を公式のレース確定とは呼ばない。

### 採用: 発走前の限定的な再取得は維持する

出走取消、騎手変更、馬体重など初回公開後の変更が予想入力に影響する。最初の成功だけで永久停止せず、発走前だけ現在の定期間隔を上限として更新する。

### 不採用: 最初の取得成功だけで自動取得を完全終了する

初回公開が開催数日前の場合、発走までの重要な変更を取り込めない。アクセス削減効果は大きいが、予想データの鮮度を損なう。

### 不採用: 開催日が過ぎたかだけで停止する

当日の最終レース後から日付変更まで不要な取得が残り、ユーザーが指摘した問題を十分に解消しない。

### 不採用: 日付ジョブが動くたび全レースを再取得する

後半レースの更新に必要なのは未発走レースだけであり、終了済みレースの詳細再訪に必要性がない。

## Acceptance criteria

- 公式結果確認済みのレースは、同日の未発走レースを更新する日付ジョブ内でも出馬表詳細ページを再取得しない。
- 発走時刻が判明しているレースは、JST で発走時刻に到達した後、出馬表詳細ページを自動取得しない。
- 発走時刻不明の過去日レースは自動再試行しない。
- 未発走かつ結果未取得のレースは、初回公開後も設定された定期間隔の範囲で更新対象にできる。
- 未公開の未来レースは発表予定日まで待機し、発走前に限って再試行する。
- 発走時刻到達を「出馬表取得終了」、確定着順と払戻の取得成功を「公式結果確認済み」として別状態・別判定で扱う。
- 対象日の全レースが出馬表取得終了、または日別結果収集が `Complete` の場合、成功済み `RaceCardCollection` を定期計画が `Ready` に戻さない。
- 同一開催日に出馬表取得終了と未発走のレースが混在する場合、レース一覧の確認後、未発走レースだけの出馬表詳細を取得する。
- 出馬表取得終了後も、管理者による明示的なレース再取得は実行でき、自動周期取得は再開しない。
- スキップ、未公開、再試行可能エラーをジョブ詳細または取得状態で区別できる。
- 常駐モードと `--once` / Lambda モードで同じ必要性判定になる。
- 出馬表取得の成功済みデータ、予想候補登録、結果収集、手動再取得、停止・保留・再開に回帰がない。

## Delivery plan

1. 日付単位で発走時刻と結果有無を返す照会契約、および自動取得必要性の純粋な判定ロジックを追加する。
2. 定期計画で全レース出馬表取得終了・日別結果完了の日付を再登録しないようにし、成功済みジョブが維持されることをテストする。
3. 日付ジョブ内で出馬表取得終了レースの詳細遷移を除外し、混在日のテストを追加する。
4. 未公開・失敗の再試行に発走時刻の上限を適用し、時刻境界と発走時刻不明の過去日をテストする。
5. 常駐・単発実行、予想候補登録、結果収集、手動再取得の回帰を検証する。
6. 正本ドキュメントと検証結果を同期する。

各段階で関連テスト、ビルド、`git diff --check`、`git status` を確認し、目的単位でコミットする。

## Deviations and follow-up

- 本記録は `Proposed` であり、プロダクションコードとデータベースは変更していない。
- 日付単位のレース一覧確認自体も不要にするには、開催日全体の出馬表取得終了状態を確実に永続化する必要がある。本変更では日別結果完了または全レースの出馬表取得終了から導出し、専用画面は追加しない。
- レース単位ジョブへの全面移行、発走直前の更新間隔最適化、JRA アクセス量のメトリクス可視化は、必要性が確認された場合に別変更として扱う。
