Status: Proposed evidence inventory; not an approval record.

**Governing contract:** canonical paths, dispositions, `/api/v2` namespace, no-alias cutover, and resolved dependencies are in `README.md`. This table's proposed method/path and target-file columns are synchronized to that contract. D1–D11 and the earlier compatibility recommendation are historical analysis, superseded by the governing proposal.

## Scope and counting method

The inventory covers every Minimal API route registered by the collection-related endpoint registration methods called from `Program.cs:280-285`: Collection Platform, Collection Monitoring, Race Odds, Race Entry Repair, Subject Collection, and Prediction Scheduling. The existing HTTP API key middleware applies to all `/api/**` routes (`ApiKeyApplicationBuilderExtensions.cs:7-36`). There is no per-route admin role policy in these registrations. Additional race-write/lease filters and in-handler locks are listed below.

The count was cross-checked by enumerating each `.MapGet/.MapPost/.MapPut/.MapPatch/.MapDelete` registration in these six files. Collection Platform routes are grouped under `/api/admin/collection` and `/api/internal/collection`; the remaining paths are absolute as shown in the source. The proposed cutover removes all 69 old registrations and installs 58 canonical routes (48 replacements plus ten merged endpoints); CP-24 has no replacement or handler. Handler targets below follow the prior design contract: one operation per `Endpoints/<Feature>/<Operation>Endpoint.cs`, with only route registration in `Extensions/EndpointExtensions.cs`.

Status shorthand: “200” means current code returns `Results.Ok(...)`; “202” means `Results.Accepted(...)`; “204” means `Results.NoContent()`. “Default binding/exception” means no explicit application error mapping is present in that handler. Proposed status is a recommendation, not a frozen decision. D1–D11 are unresolved design dependencies listed after the matrices.
