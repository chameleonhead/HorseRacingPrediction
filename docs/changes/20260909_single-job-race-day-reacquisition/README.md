# 開催日再取得を単一ジョブで一括実行する

- Status: Proposed
- Owner: HorseRacingPrediction maintainers
- Created: 2026-09-09
- Updated: 2026-09-09

## Context

現行の `RaceDayReacquisition` はJRA公式情報から指定日のレースを発見した後、レースごとの `RaceReacquisition` 集約子ジョブを登録する。各子ジョブは独立したブラウザーセッションを作り、開催選択から対象レースまでの公式導線を再探索するため、1日分の完了に時間がかかる。

利用者は、レース別ジョブへ分割せず、指定日全体を一括したジョブとして実行することを希望している。

## Goals

- `RaceDayReacquisition` 1件の実行内で、その日の全開催場・全レースを再取得する。
- 1つのブラウザーセッションを再利用し、レースごとのセッション起動と共通導線探索を削減する。
- 1レースの取得失敗で残りのレースを中断しない。
- 同じ日付の有効な依頼に対する既存の重複抑止、保留、停止、監査を維持する。

## Non-goals

- 通常のレース単位再取得操作を削除すること。
- 複数日・期間指定を追加すること。
- Collector/Lambdaの実行時間上限を変更すること。
- 複数Workerによる同一開催日の並列取得。

## Experience and interaction design

管理画面の「開催日を再取得」と日付入力は維持する。確認文から「レース単位のジョブへ分割する」を削除し、「1件のジョブで開催日全体を順次取得する」と説明する。

送信後は従来どおり `RaceDayReacquisition` の詳細へ遷移する。レース別の子ジョブ一覧は表示されず、日付ジョブ自身の実行中・完了・失敗・保留状態を確認する。失敗時の詳細には、失敗した競馬場・レース番号・処理種別をまとめて表示する。

## Technical impact

- `ExecuteRaceDayReacquisitionAsync` は、公式レース発見後に `ScheduleJobAsync(RaceReacquisition)` と `WaitForCollectionDependenciesAsync` を呼ばない。
- 公式レース発見と全レース再取得で同じ `IJraSession` を使用する。
- 登録済みレースIDとの照合は日付ジョブ内で一度だけ行う。未登録レースには現行どおり決定論的IDを使用する。
- 各レースについて、公式掲載期間内なら出馬表、当日以前なら結果・天候・馬場・払戻を既存workflowで更新する。
- レース単位の非致命的エラーは対象識別子付きで収集し、残りのレースを継続する。全対象の処理後、エラーが1件でもあれば日付ジョブを失敗として報告する。
- 取得対象が0件なら現行どおり正常完了する。全対象が未公開なら日付ジョブを公開待ちとして再投入せず、取得できなかった対象を失敗理由へ記録する。
- 既存の14分内部期限を超えた場合はタイムアウトとして失敗し、収集全体停止の現行契約に従う。期限延長や実行分割による自動再開は本変更に含めない。

## Decisions

### 採用: 単一ジョブ・単一セッション・逐次取得

利用者が求める一括実行を満たし、時間増加の主因であるセッション作成と共通ナビゲーションの反復を除く。JRAへの同時アクセスを増やさないため、同一ジョブ内の並列取得は行わない。

### 採用: 部分失敗後も残りを継続し、最後にジョブを失敗させる

途中の1レースで日付全体が未処理になることを防ぎつつ、「全レース再取得」の一部欠落を成功として隠さない。再実行は同じ日付ジョブの新しい試行として、冪等な更新を日付全体へ再適用する。

### 不採用: レース別子ジョブを維持して優先度だけ上げる

セッション起動と導線探索の反復が残り、利用者が指定した一括ジョブにならない。

### 不採用: 開催場ごとの並列処理

短縮余地はあるが、一括した単一処理の単純性を損ない、JRAへの同時アクセス量とブラウザー資源使用を増やす。

## Acceptance criteria

1. 開催日再取得の依頼1件につき、`RaceDayReacquisition` 以外の子ジョブを作成しない。
2. 公式開催日程からDB未登録分を含む全開催場・全レースを発見する。
3. 発見と全レース取得に1つのブラウザーセッションを再利用する。
4. 公式掲載期間内の出馬表と、当日以前の結果・天候・馬場・払戻を既存の更新契約どおり保存する。
5. 1レースが非致命的エラーでも後続レースを処理し、失敗対象を日付ジョブのエラーへ集約する。
6. 全対象成功時だけ日付ジョブを完了にする。対象0件は開催なしとして正常完了する。
7. 同日付の有効依頼の重複抑止、保留、全体停止、監査、リランが維持される。
8. 通常のレース単位再取得機能に回帰がない。
9. 管理画面は単一ジョブで実行することを説明し、子ジョブ進捗を案内しない。
10. Collector/API/UIの関連テスト、solution build、`git diff --check` が成功する。

## Delivery plan

1. 日付再取得の発見処理を既存セッション受け取りへ整理する。
2. レース単位更新を既存セッションで呼べる内部処理へ整理し、日付ジョブから全対象を逐次実行する。
3. 子ジョブ非生成、セッション再利用、部分失敗継続、完了・失敗を自動テストする。
4. 管理画面説明、正本文書、検証記録を同期する。
